Admin Auth Guide

How PRML's admin authentication works, how to sign in, how to rotate the password, and what triggers a sign-out.

Quick start:
  1. Go to any /admin/ page.
  2. The Sign In overlay appears. Type your starter password.
  3. You stay signed in for up to 8 hours. Idle 30+ minutes → signed out.
  4. Rotate the password from admin/dashboard.html → Admin Session card → Change Password.

1. How the auth works

The auth system is client-side only (no backend session server) but designed so the password never appears in the source code or on disk:

  • SHA-256 hash: the only thing in js/admin-auth.js is a hash of the password. Even with full source access, the password cannot be read.
  • Session token: when you sign in, your browser stores a session object in localStorage with three timestamps: created, idle expires, absolute expires.
  • Activity tracking: mouse, keyboard, touch, and scroll events each bump the idle timer forward (throttled to once per minute to avoid storage churn).
  • Two timeouts:
    • Idle: 30 minutes with no activity → sign-out overlay.
    • Absolute: 8 hours from sign-in regardless of activity → sign-out overlay.
  • Cross-tab: open as many admin tabs as you want, one sign-in covers all of them.

2. Signing in

  1. Visit any admin URL, e.g. https://prmlrecords.com/admin/dashboard.html.
  2. The page blurs and a dark overlay appears with a single password field.
  3. Type the password and press Enter (or click Unlock Admin).
  4. If correct, the overlay disappears and you have admin access for the next 30+ minutes.
  5. If incorrect, you see "Incorrect password" and the field clears. Try again.

3. Rotating the password

Option A — from the Admin Session card (recommended)

  1. Open admin/dashboard.html.
  2. Find the Admin Session card.
  3. Click Change Password.
  4. Enter a new password (minimum 10 characters), confirm it, click Rotate.
  5. The dialog shows a SHA-256 hash. The new password works immediately on this browser.
  6. To lock the new password in for every device + browser: paste the hash into js/admin-auth.js at the SECRET_HASH constant, commit, then /prml-deploy.

Option B — from the browser console (power user)

// On any admin page, open DevTools (F12) > Console:
await PRMLAdmin.rotatePassword('newPasswordHere')
// Returns { ok: true, hash: '...', note: '...' }
// Paste the hash into SECRET_HASH in js/admin-auth.js and redeploy.
Why the two-step process? The browser-side change is instant for you but only persists on this device until you close the tab. To make a new password permanent for the team, the hash must be in the source code.

4. Signing out

Three ways:

  • Manual: click Sign Out in the Admin Session card (or Log Out in the header).
  • Idle: walk away for 30+ minutes → on return, you see the sign-in overlay.
  • Hard expiry: after 8 hours from sign-in → overlay appears even if you were active the whole time.

5. What does not protect

This auth model has known limits because the site is fully static:

  • The page HTML and data files are still served by the CDN unauthenticated — auth happens in the browser, not at the network layer.
  • A determined attacker could disable JS or read network responses directly. For high-sensitivity data (Stripe keys, real customer records), use server-side endpoints with their own auth (e.g. /api/promo-analytics uses a separate PROMO_ADMIN_TOKEN).
  • Anyone with the password can sign in. There is no MFA. Rotate immediately if you suspect a leak.
  • noindex + no-referrer meta tags are on every admin page, so search engines should skip them.

7. Troubleshooting

SymptomFix
Overlay never disappears after correct passwordCheck browser console for SHA-256 errors. Crypto.subtle requires HTTPS (live site is fine, localhost may not be).
Signed out immediately on every page loadSECRET_HASH may be wrong. Recompute from your password: await PRMLAdmin.sha256Hex('yourpassword') — if the result does not match what's in js/admin-auth.js, redeploy with the correct hash.
I forgot the password and don't have a hashGenerate a new one locally: python3 -c "import hashlib; print(hashlib.sha256('newpw'.encode()).hexdigest())", paste the hash into js/admin-auth.js, redeploy. The new password is the one you hashed.
Want a different timeoutEdit IDLE_TIMEOUT_MIN and SESSION_TTL_MIN at the top of js/admin-auth.js.
