Discount System Guide

Everything about the site-wide promo banner and Stripe coupon system. Two source-of-truth files, live counters, auto-apply URLs.

Two files control everything:
1. js/promo-config.json — what shows on the site (banner, copy, URLs)
2. Stripe Dashboard → Coupons — what actually discounts at checkout
The coupon code (uppercase) in the JSON must match the coupon ID in Stripe exactly.

1. ONE-TIME STRIPE SETUP — Create the coupons

Go to Stripe Dashboard → Coupons and create these 5 coupons. The ID field is the most important — it must match the JSON exactly.

Coupon ID (uppercase)TypeDiscountMax RedemptionsPurpose
FIRST9_SETUP_FREEAmount off$15.999Waives the $15.99 setup fee on the first 9 custom NFC orders. Auto-disables when full.
PRML5Percent off5%UnlimitedNewsletter / first-time visitor discount
PRML10Percent off10%UnlimitedEmail campaigns / IG link-in-bio
PRML20Percent off20%UnlimitedBlack Friday / launch events
BELTLINE10Percent off10%Unlimited (or set to 100)Beltline pop-up scan-our-card discount
Important: Coupon IDs are case-sensitive but our system normalizes to UPPERCASE. Always create coupons with UPPERCASE IDs in Stripe (e.g. PRML10 not prml10) so the URL ?promo=PRML10 matches.

2. Launch a promo campaign (banner across whole site)

1
Open js/promo-config.json on your computer.
2
Either edit an existing promo (e.g. "first-9", "beltline-may") or add a new one to the "promos" object. Each promo needs: 
"my-promo": {
  "label": "Spring Launch",
  "headline": "20% OFF — Spring Drop, This Week Only",
  "sub": "Use code PRML20 at checkout · ends Sunday",
  "stripe_coupon_code": "PRML20",
  "live_counter": false,
  "counter_text": null,
  "counter_value_fallback": null,
  "cta_text": "Shop Now →",
  "cta_href": "shop.html?utm_source=prmlrecords&utm_medium=promo-banner&utm_campaign=spring-launch",
  "auto_apply_url": "?promo=PRML20",
  "theme": "red-on-cream",
  "starts_at": "2026-05-15",
  "ends_at": "2026-05-22",
  "show_on": ["all"],
  "hide_on": ["confirm/index.html"]
}
3
Set "active_promo": "my-promo" at the top of the file.
4
Run /prml-cache-bust then /prml-deploy. Banner appears on every page within 60 seconds.

3. Pause / kill the promo

Set "active_promo": "off" in js/promo-config.json, run /prml-deploy. Banner disappears site-wide. The Stripe coupon stays active so you don't lose redemption history.

4. Auto-apply discount URLs (for marketing campaigns)

Send these URLs in emails, IG bio, SMS — the discount auto-applies when the customer reaches checkout. They never type a code.

Send this URLWhat happens
https://prmlrecords.com/?promo=PRML1010% off auto-applied at checkout
https://prmlrecords.com/shop.html?promo=PRML2020% off auto-applied at checkout
https://prmlrecords.com/services.html?promo=FIRST9_SETUP_FREE$15.99 setup fee waived (capped at 9)
https://prmlrecords.com/?promo=FRIEND1515% friends-and-family
The promo code is captured by js/promo-banner.js on landing, stored in the visitor's browser, and silently sent to /api/checkout when they pay. They can also remove it on the checkout page.

5. The "X spots left" live counter

Set "live_counter": true on a promo to show a real-time count. The banner calls /api/promo-status?code=COUPON_ID which counts actual succeeded payments tagged with that coupon. Cached 30 seconds at the edge.

When the count hits the coupon's max_redemptions:

  1. The webhook (/api/webhook) deletes the Stripe coupon — hard kill switch, no further redemptions possible
  2. /api/promo-status returns 410 Gone on next call
  3. js/promo-banner.js hides the whole banner and clears any stored coupon
  4. Customers who already had the URL get the same "promo invalid" message at checkout

6. Add a brand-new discount code

1
Create the coupon in Stripe → Coupons with an UPPERCASE ID like SUMMER25.
2
Optional — add to storewide_codes in js/promo-config.json for documentation: 
"SUMMER25": { "label": "25% Summer Sale", "percent_off": 25, "purpose": "June email", "auto_apply_url": "?promo=SUMMER25" }
3
That's it — the code now works at checkout (auto-apply via URL or manual entry). No code deploy needed if you're not making it the active banner promo.

7. How to audit which discounts ran

  • Stripe Dashboard → Coupons → [coupon] → Times redeemed shows live count (auto for Checkout Sessions; for raw PaymentIntents we count via metadata search)
  • Stripe Dashboard → Payments — filter by metadata promo_code equals the coupon ID
  • Airtable → Orders — every paid order has the promo code (if any) in the Stripe metadata

8. Troubleshooting

ProblemFix
Banner not showingCheck active_promo spelled correctly, dates valid, page not in hide_on
Counter shows fallback (—) foreverCoupon ID typo, or checkout_api_base URL wrong in config
"Promo code not found" at checkoutCoupon ID in JSON doesn't match Stripe (case sensitive!) — recreate in Stripe with UPPERCASE
Discount didn't apply but customer says they used the URLStripe coupon was deleted (capped) OR expired — check Stripe → Coupons
Promo banner shows after cap was reachedEdge cache (30s) — wait a minute. If persistent, check /api/promo-status directly
